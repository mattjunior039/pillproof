# Release: PillProof models on Hugging Face

What is released:
- Public model repos for the two shipped builds. These are the per-size defaults in `app/models.json`, chosen on dev ([gate2.md](gate2.md)). Round 4 was not built, so r1 stays.
- The public app downloads them from Hugging Face, not from `~/waicy-work`.

| App key | Size | HF repo | Weights |
|---|---|---|---|
| `r1-ft` | 2B (primary) | `<user>/PillProof-Qwen3.5-2B-r1-q4f16_1-MLC` | 1.0 GB |
| `lite-r1-ft` | 0.8B (lite, iPhone 17e) | `<user>/PillProof-Qwen3.5-0.8B-r1-q4f16_1-MLC` | 426 MB |

Each repo contains:
- the MLC `q4f16_1` weights, tokenizer and `mlc-chat-config.json`, exactly as tested in the Gate 2 browser check;
- the WebGPU model library (`Qwen3.5-*-q4f16_1_cs1k-webgpu.wasm`);
- the Qwen `LICENSE`;
- a model card (`README.md`), generated by `train/scripts/hf_release.py` from `app/models.json`.

The model cards cover:
- intended use (label-grounded answers in the demo; not medical advice);
- prompt format;
- WebLLM usage;
- training data and the AI-rewrite disclosure;
- dev metrics with CIs and the base-model comparison;
- known limits: over-declining, 4-bit flips, restatement meaning, single-grader audits.

## License review (Nov 24, 2026)

No blocker found. This is a reading of public terms by a student project, not legal advice.

| Component | Terms | Effect on release |
|---|---|---|
| Qwen3.5-2B / 0.8B base weights | Apache-2.0 (`LICENSE` in the Qwen repos) | Fine-tuned derivatives may be released. Keep the license and state the changes; the model card says "LoRA fine-tune, merged, quantized". |
| FDARxBench (github `xiongbetty/FDARxBench` @019785d; Xiong et al., arXiv:2603.19539; Zenodo DOI 10.5281/zenodo.22073747) | Apache-2.0 for code and data | Training on it and releasing weights is allowed, with attribution, given in the card. |
| FDARxBench's QA pairs were generated with GPT-4o-mini | OpenAI's terms bind the people who generated the outputs (the FDARxBench authors), who released the data under Apache-2.0 | Not blocking. Disclosed in the card. |
| FDA label text (DailyMed / openFDA SPL) | US government work, public domain | No restriction. |
| Plain-language ANSWER lines written by Claude Sonnet 5.5 (train/valid targets) | Anthropic Commercial Terms: the customer owns outputs. The terms bar using the services to build a *competing* product or to train competing AI models. | A narrow on-device model that restates FDA-label sentences is reasonably not a competitor to Claude. The wording is broad, though, so the ambiguity is noted here and the rewrite is disclosed in the card. |
| Claude verifier (round 4) | Same terms | It changed no released data; it only validated against human verdicts and failed ([data.md](data.md)). |
| WebLLM 0.2.88 and the `binary-mlc-llm-libs` v0_2_87 `.wasm` library | Apache-2.0 | The unmodified `.wasm` is redistributed in each repo. |
| bge-small-en-v1.5 (retrieval embeddings in the app) | MIT | Not part of these repos; the app loads it separately. |

The repo card metadata says `license: apache-2.0`.

## Steps

```bash
PY=~/waicy-work/envs/mlx/bin/python
$PY train/scripts/hf_release.py stage                 # ~/waicy-work/release/<repo>/ (APFS clones of the MLC dirs)
hf auth login                                         # the release account, not jmamitha
$PY train/scripts/hf_release.py upload --user <user>  # refuses unless `whoami` is <user>, and never jmamitha
$PY train/scripts/app_models.py --hf-user <user>      # adds hf_repo / model_url / model_lib_url to app/models.json
# browser check: gate1 page, ?models=hf-r1-ft,hf-lite-r1-ft (keys read the URLs from app/models.json)
```

`model_url` is what WebLLM's `model` field takes; WebLLM appends `resolve/main/`. `model_lib_url` points at the `.wasm` in the same repo. The app should prefer these fields when they are present.
