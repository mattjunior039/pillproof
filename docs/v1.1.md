# PillProof v1.1: show label sentences instead of declining

A post-freeze fix, tested on a fresh question set (T7). v1.0 stays exactly as evaluated in [final-eval.md](final-eval.md).

- **v1.0** = tag `freeze-2026-11-25` (commit 557c3f2). Unchanged.
- **v1.1** = tag `v1.1-2026-11-26`, on the commit that implements the rule below. Models, retrieval, prompts and the quote/number/qualifier checks are the same as v1.0. Only the display rule changes.

**Why.** In the final evaluation the fine-tuned model over-declined consumer-phrased questions. On T3, the full app (F-2B) gave an acceptable answer on 55.2%, while the passage-only fallback D, which only shows label sentences, reached 69.9% (final-eval.md, loss list).

## Pre-registration

This section was written and committed **before** v1.1 was run on any question, and before T7 existed. It is not edited after the runs. Results go in a separate section below.

### The rule

It applies only to the **first step: the user's own label**. Backup sources keep the v1.0 logic exactly: other labels, FDA consumer pages, DDInter, and the web step, including the label search inside it. Web search behaviour is unchanged.

**When it fires.** v1.0 would show one of these for the user's own label:
- (a) a **decline**: the model replied NOT IN LABEL; or
- (b) **"The closest sentences in the label"**: the checks withheld the model's reply. Either the reply was unusable (unparseable, or it cites a sentence not in the prompt), or it cited only sentences that mention none of the asked topics.

**The relevance gate.** All three must hold:
1. The question has at least one topic concept (`concepts()` in `app/src/lib/query.ts`, unchanged).
2. At least one of those concepts is mentioned somewhere in the label (`coverage().covered`).
3. `topSentences()` returns at least one readable label sentence that mentions a covered concept and scores at least 0.6 × the best score. These are v1.0's ranking and filters, unchanged.

**If the gate passes:**
- Show up to 3 of those sentences, highlighted, with their section names, under **"Your label says:"**. This is v1.0's existing heading for extractive quotes from the user's own label. The brief's "The label says:" is the same display; "Your" tells it apart from backup labels.
- For each asked concept the label does not mention, keep v1.0's note: "The label does not mention 'X'. That does not mean it is safe or unsafe."
- No model text is shown, and backup sources and web search do not run.

**If the gate fails** (no topic concept, none mentioned in the label, or no qualifying sentence): v1.0 behaviour. The app declines or shows "not found", then runs backup sources, then web search.

**Difference from v1.0.** v1.0 already quoted sentences after a model decline, but only when *every* asked concept was in the label. v1.1:
- drops the "every concept" condition, so a partly covered question now quotes the covered part and says what is missing;
- shows case (b) under "Your label says:" with up to 3 sentences, instead of 2 under "The closest sentences in the label".

**Thresholds.** No new thresholds. The 0.6 relative cutoff, the 3-quote maximum, the topic list and the concept matcher are v1.0 constants. They were set during development on dev questions (docs/app.md). Nothing is tuned on T3, T7 or any test output, before or after the runs.

**Known risk.** On a partly covered question ("Can I take it with cranberry juice in the morning?"), v1.1 quotes the label's timing sentences and says cranberry is not mentioned, where v1.0 would have gone to the backups and the web, which might have answered the cranberry part. On a label-silent question, the quoted sentences could be read as an answer. The harm checks below measure this.

### T7: a fresh test set

- **Size.** About 100 consumer-phrased questions about common medicines: about 70 answerable from the label and about 30 label-silent.
  - Written in the T3 style ([t3.md](t3.md)): plain questions an older adult might ask about their own medicine.
  - About half the drugs are **not in T3**, including some over-the-counter products.
- **Labels.** For each drug, the current openFDA label, parsed and numbered exactly like T3 (`spl.py`, `sentences.py`).
- **Drafting.** Written by Claude (Copilot sub-agents with a fresh context). They see only the numbered label text and the T3 method. They have no access to any system output, run file, grade or final-evaluation result.
  - Each answerable item gets gold sentences, as verbatim snippets of label sentences, and a reference answer taken from them.
  - Each label-silent item gets a reference answer saying the label does not cover it, a probe answer and search patterns, as in T3.
- **Automated item check only. No human reviewed T7, and this is disclosed with every result.** The check is `datapipe medlabel_data.t7 build`, the T3 checks applied to T7:
  - every gold snippet matches exactly one label sentence;
  - the reference answer passes the app's restatement check against the gold sentences;
  - the gold sentences are in the current openFDA text;
  - for label-silent items, the decline support check over every label sentence must not find the probe answer supported, and the keyword-scan hits are listed.
  - A second, separate Claude sub-agent reads each item against the numbered label and marks it keep or drop. It cannot edit items. Dropped and failing items are removed.
- **Freeze.** The SHA-256 of `t7_items.csv` and `items_app.jsonl` is committed in this file before any system is run on T7. After that, no item is changed.

### Runs (each once, no reruns)

The model servers, tiers and harness (`app/eval/final_harness.ts`) are as in the final evaluation. One GPU job runs at a time.

- **F** = the full app: the r1 fine-tune and checks, with backup sources and web search on.
  - F-2B: desktop tier, `r1-ft`. F-0.8B: phone tier, `lite-r1-ft`.
  - Web search uses Tavily with a 15 s timeout and one retry. The harness's query cache is shared, so a search repeated by the v1.1 run reuses the v1.0 run's result. This keeps the pair comparable; it is disclosed.
- **v1.0** runs from a checkout of tag `freeze-2026-11-25`, plus the final-eval harness file. **v1.1** runs from tag `v1.1-2026-11-26`.

| Run | Set | Role |
|---|---|---|
| v1.0 F-2B, v1.1 F-2B, v1.0 F-0.8B, v1.1 F-0.8B | T7 | **primary** |
| B-2B, B-0.8B (base model plus label passages, phone tier, label only) | T7 | context |
| D (passage-only, phone tier) | T7 | context |
| v1.1 F-2B, v1.1 F-0.8B | T3 (143) | **post-hoc**, not primary: T3 was seen before v1.1 was designed |
| v1.0 vs v1.1 display on the recorded C-2B phone replies (no model run) | T1 FDARxBench refusal items (549) | harm check |

- The label-only v1.1 C result is also reported. It is the first step of each F run.
- **T1 refusal replay.** For each refusal item, the reply C-2B gave in the final evaluation is passed through the v1.0 and the v1.1 app display logic. The label is built from the FDARxBench chunks, with lexical retrieval scores only (no embeddings), and this is disclosed. Every item whose display changes is AI-graded.

### Grading

- **Grader.** The same AI grader as the final evaluation: Claude Sonnet 5.5, rubric `GSYSTEM` in `train/scripts/final/grade_ai.py`, unchanged.
- **What it sees.** The question, the reference answer, the gold sentences, and for label-silent items "DOES THE FDA LABEL ANSWER IT: no".
- **Blind.** No system names; tasks are shuffled; identical answer texts are graded once.
- **No human grading.** Its agreement with human verdicts is reported in final-eval.md.

### Metrics

**Primary: T7 acceptable**, per size, v1.1 F − v1.0 F. Acceptable means verdict `correct`, or `declined` on a label-silent item; this is the T3 definition.
- Reported with a paired 95% bootstrap CI, resampling whole drugs, 2,000 resamples (`common.paired_boot`).

**Harm:**
- the number of answers graded `harm: serious` on T7, per system;
- the `wrong` rate on label-silent T7 items;
- the same on the label-silent T3 items (post-hoc), and on the changed T1 refusal items.

**Secondary:**
- correct on answerable items;
- declined and wrong on label-silent items;
- how often the rule fires (first step changed from v1.0);
- B, D and v1.1 C as context.

### Ship criterion (fixed now)

**Ship v1.1 only if both hold at both sizes (2B and 0.8B):**
1. v1.1 F acceptable on T7 is higher than v1.0 F (point estimate of the paired difference > 0);
2. v1.1 F has no more `serious`-harm answers on T7 than v1.0 F.

**Otherwise, don't ship.**

- If the improvement's CI includes 0, the recommendation says the gain is not statistically clear.
- If harm rises on the post-hoc T3 label-silent items or on the T1 refusal replay, the recommendation flags it. These checks do not change the decision.
