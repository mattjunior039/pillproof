## Files

| file | what |
|---|---|

| `t3_spec.json` | source of truth: the hand-written items (made from `work/items_<drug>.json`) |

Rebuild (from `datapipe/`, no model, no GPU):

```bash
uv run python -m medlabel_data.t3 snapshot   # fix the label for each drug, number sentences
uv run python -m medlabel_data.t3 build      # resolve gold, run checks, write t3_draft.*
```

`build` carries over existing `user_status` / `user_notes` by `t3_id`. **IDs are assigned in spec order**, so after any items are dropped, edit the spec rather than renumbering by hand. The build stops (exit 1) on any error, so no draft is written with a broken item.

## Which label

Per plan item 8, the app uses **the most recent openFDA label for the product**. `snapshot` takes the set ID chosen by `labelfetch` (`config/t3_drugs.json`) and the version that openFDA serves now. It parses that version's SPL XML with the same `spl.py` / `sentences.py` the app uses.

- **Pantoprazole.** openFDA serves v48, but the v48 XML is not on DailyMed yet. The numbering comes from v47 (`source` in `snapshot.json` says so), and every pantoprazole gold sentence is in the Medication Guide, which did not change.
- **Gold sentences are checked against openFDA.** For every drug, `build` checks that each gold sentence's words appear in the current openFDA text (`gold_in_openfda`). It ignores a leading list number, which openFDA drops. All 100 answerable items pass.
- **Patient section preferred.** Where the label has a Medication Guide or Patient Information, the gold sentences come from it (82 of 100 answerable items, counting section 17 Patient Counseling). Otherwise they come from the prescriber sections. These labels have no patient leaflet: furosemide, hydrochlorothiazide, levothyroxine, lisinopril and metoprolol.
- **Other places with the same answer.** If the same answer appears elsewhere in the label, it is listed under `alt_gold`. Those are acceptable citations too.

## Gold sentence numbering

`S<section>.<n>`: `section` is the index of the section in the parsed label, and `n` is the sentence number within that section, from 1, exactly as `sentences.py` splits it. This is the number the model sees in its prompt. `L<n>` is a running number over the whole label, for convenience.

**How gold is written.** Gold is written as a verbatim snippet of each sentence. `build` checks that each snippet matches exactly one sentence of the named section. When a section repeats a sentence word for word (for example, a missed-dose instruction given for two dose schedules), the item pins the number with `{"n": …, "text": …}`, and `build` checks that the text matches that sentence.

## Questions

There are 143 questions on 25 drugs (4–7 per drug):
- 100 are answerable from the label.
- 43 (30%) are **not answerable** from the label, so the right response is to decline and refer the user to a pharmacist or doctor.

The target was about 120. The draft is deliberately over target so the student can drop weak items without falling short.

**How the questions were written.** Each question is phrased as a patient would phrase it: brand or generic name, everyday words, sometimes a second medicine or food named casually ("Can I take Advil with it?"). Questions are about the listed drug, and "can I take X with it?" is answered only from that drug's label.

## Not-answerable items: how absence was confirmed

"The label doesn't mention it" never means "it is safe". The reference answer for these items always says the label doesn't answer it and to ask a pharmacist or doctor; it never says yes or no. Absence was confirmed over the **whole label**, not one section, in three ways:

1. **Support check.** The decline check from the training data (`fdarx/support.py`, threshold 0.5) runs over every sentence of the label, with nothing removed, on a *probe answer*. A probe answer is what the label would say if it did answer, for example "Alcohol can increase the blood-pressure-lowering effect of amlodipine". The check is deliberately loose (word overlap over up to 4 sentences), so it flagged 33 of the 43 items. Every flagged item was read by hand, and the reason it is not actually an answer is recorded in `support_review` in the spec and shown in `t3_checks.md`. `build` refuses a flagged item that has no `support_review`.
2. **Keyword scan.** Each item has regex search terms (for example `alcohol|ethanol|drink`, `grapefruit|citrus`, `St\. John|herbal`). Every hit in the label, and in the current openFDA text, is listed in `t3_checks.md` and was read. Common false hits include solubility statements ("soluble in ethanol"), alcohols in inactive ingredients or ink, "alcoholic cirrhosis" in a study population, "methanol", and comparator drugs named in trials.
3. **Reading.** The full numbered label (`labels/<ingredient>.txt`) was read around every hit. Each item's `decline_evidence` field says what the label does and does not say.

**One item was converted.** "Can Fosamax make my hair fall out?" was drafted as not answerable, but the support check pointed to section 6.2 Postmarketing Experience, which lists "alopecia". It is now answerable with that sentence as gold. Some other items are borderline and are marked in `author_notes` for the student to decide. For example, the amlodipine alcohol item: the label says amlodipine doesn't change ethanol exposure, but says nothing about the effect of drinking.

## Integrity rules

- T3 was written blind to the systems. No model outputs, prediction files or Gate 2 eval outputs were opened while writing it, and no model has been run on it. It must not be run until the student locks it.
- T3 is never used for training or tuning, and it is never rewritten into plain language by a model.
- Grading is blind to which system wrote each answer (plan section 7).
